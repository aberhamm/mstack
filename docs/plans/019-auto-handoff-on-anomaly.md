## Requirements

When anomaly detection (plan 018) fires, the agent currently has no defined
response — it would either retry (looping) or exit silently (losing context).
The agent must write a handoff checkpoint file with full anomaly details so
the user can resume from a clean state.

**Acceptance criteria:**

- [ ] When manifest.sh check returns non-zero (anomaly detected), mstack-run writes a handoff checkpoint file directly to `.mstack/handoffs/`
- [ ] The handoff file follows the documented format from mstack-handoff (markdown with CONTEXT ONLY header, Goal, Current state, Files touched, What's been tried and failed, Next step, Open questions)
- [ ] The "What's been tried and failed" section includes the anomaly type, reason string, and manifest snapshot
- [ ] The "Next step" section suggests specific recovery actions based on anomaly type
- [ ] mstack-run outputs `[mstack] ANOMALY: <type> — <reason>. Handoff checkpoint saved to .mstack/handoffs/<filename>` to stdout
- [ ] The output includes `resume from handoff <short-summary>` instruction
- [ ] The ANOMALY output signal is distinct from normal completion ("Backlog clear") and normal failure ("plan N: failed:reason") so /goal stops the loop
- [ ] mstack-run exits after writing the handoff — no retry, no continuation
- [ ] Manifest is NOT deleted on anomaly (preserved for debugging)

## Design

**Why write directly instead of invoking mstack-handoff:** The mstack-handoff
skill calls AskUserQuestion to ask the user for delivery mode (chat vs
checkpoint). In an autonomous /goal context there is no user to answer.
Writing the handoff file directly avoids the blocking prompt while producing
the same artifact in the same location with the same format.

**Anomaly response flow:**

1. `manifest.sh check` returns non-zero with reason on stdout
2. mstack-run captures the anomaly type and reason
3. mstack-run reads the execution manifest for context (completed plans, pending plans, iteration count)
4. mstack-run writes a handoff checkpoint file to `.mstack/handoffs/` using the naming convention `{YYYY-MM-DD}-handoff-{NN}-anomaly-{type}.md`
5. mstack-run outputs the ANOMALY signal line with the filename and resume command
6. mstack-run exits the iteration

**Handoff file content (generated by mstack-run, not the skill):**

```markdown
<!-- CONTEXT ONLY: Do not start work. Wait for the user to run a command. -->

# Handoff: Anomaly during plan execution — {anomaly_type}

**Date:** {YYYY-MM-DD}
**Branch:** {current git branch}

## Goal
{the original /goal command or scoped plan IDs}

## Current state
Completed plans: {list from manifest terminal_ids}
Pending plans: {scoped IDs not in terminal_ids}
Iteration count: {from manifest}
Anomaly detected at iteration {N}.

## Files touched
- .mstack/execution-manifest.json (preserved for debugging)

## What's been tried and failed
- Anomaly type: {type}
- Reason: {reason string from manifest.sh check}
- Manifest state at anomaly: {JSON snapshot or summary}

## What's been ruled out
- The plan execution loop was halted automatically to prevent infinite looping.

## Next step
{recovery suggestion from mapping below}

## Open questions
- Was the backlog intentionally modified during execution?
```

**Recovery suggestions by anomaly type:**

| Type | Suggested next step |
|------|-------------------|
| `iteration_bound` | "Check plan statuses — a plan may be stuck in-progress. Run: /mstack-status" |
| `repeat_pick` | "Plan NNN was picked twice without completing. Check if it's stuck. Run: /mstack-run NNN" |
| `no_progress` | "Last iteration made no progress. Check plan NNN status and health gate. Run: /mstack-investigate" |
| `path_divergence` | "Plan files were moved/renamed during execution. Check docs/plans/ for changes. Run: /mstack-status" |

**stdout signal for /goal:** The `/goal` evaluator must recognize
`[mstack] ANOMALY:` as a terminal signal. Add this to SKILL.md's progress
format documentation so /goal knows to stop when it sees this prefix.

**Files expected to change:**

- `skills/mstack-run/SKILL.md`: replace the TODO stub from plan 018's anomaly check with the full handoff-writing handler; update progress format docs
- `skills/mstack-run/references/progress-format.md`: document the ANOMALY signal

**Out of scope:** Modifying mstack-handoff skill. Changing /goal's behavior —
it already stops on unrecognized output patterns. The ANOMALY signal just
needs to not match the "continue" patterns.

Testing approach: unit-only
