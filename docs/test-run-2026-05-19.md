# First v2 test run — 2026-05-19

## What happened

We used mstack v2 to build mstack v2, then tested it on a fresh project to verify the full autonomous loop works end-to-end. The test project was a Python calculator with two functions (`add`, `subtract`). mstack planned, implemented, verified, and committed a feature (adding `multiply` and `divide` with division-by-zero handling) without human intervention after the plan was approved.

## What's interesting about this

This test run is self-referential in a way that feels like a turning point in how software gets built.

**The tool built itself.** The session that produced this test run started by writing 6 new SKILL.md files, integrating them into the worker pipeline, rewriting the README, and syncing to skillshare. Then — in the same session — it ran the newly-written pipeline on a fresh project to verify the whole thing works. The tool that was being built was also the tool doing the building.

**Plans are the new unit of work.** The developer's job shifted from "write the code" to "describe what done looks like." The plan file — with its acceptance criteria, file paths, and tasks — became the contract. The AI read the contract, executed it, verified its own work against the project's health checks, and committed the result. The human reviews `git log -p` afterward, the same way a tech lead reviews a junior's PR.

**The system learns from itself.** Each execution can extract patterns and pitfalls into a knowledge base (`.mstack/learnings.jsonl`) that future runs consult. A convention discovered in plan 3 becomes a constraint applied in plan 30. The codebase develops institutional memory that persists across sessions, across crashes, across context windows.

**Crash recovery carries facts, not opinions.** When the worker crashes mid-plan, the checkpoint captures what was tried and what the compiler said — not what the AI thought was wrong. The next session gets evidence and forms its own conclusions. This is a deliberate design choice: agent reasoning is the thing most likely to be wrong, so it's the one thing we don't persist.

**Verification is scored, not binary.** Instead of "tests pass / tests fail," the health check scores quality across 5 dimensions (typecheck, lint, tests, dead code, shell lint) and tracks trends over time. A plan that passes all tests but introduces 200 lines of dead code gets flagged. The score becomes a ratchet: quality can improve or hold, but regressions trigger investigation.

## The broader picture

Software development is becoming self-referential. The tools write themselves. The plans describe what to build, and the builder reads the plans. The knowledge base learns from executions, and future executions consult the knowledge base. The checkpoints recover from crashes, and the crashes teach the system what to checkpoint.

This isn't AGI. It's a loop: plan, execute, verify, learn, repeat. But the loop runs autonomously, and each iteration makes the next one slightly better informed. The developer's role shifts from writing code to designing the loop — choosing what to verify, what to learn, what to persist, and when to stop.

The interesting question isn't whether AI can write code. It obviously can. The interesting question is whether the system can maintain coherence across dozens of plans, hundreds of commits, and thousands of decisions — without a human in the loop for each one. That's what mstack is testing.
